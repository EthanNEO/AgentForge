# AgentForge 2.0 架构与调用图

> 对应 2026-11-16 当前实现。

## 用户与页面

```text
┌──────────────────────┐                  ┌────────────────────────┐
│ 任务工作台 /workbench │ ←── 同一 Run ──→ │ 编排监控台 /            │
│ 输入、计划确认、结果   │                  │ DAG、Worker、验证、事件   │
└──────────┬───────────┘                  └───────────┬────────────┘
           └─────────────────┬────────────────────────┘
                             ▼
                  ThreadingHTTPServer + Router
```

## 执行主链路

```text
POST /api/plan
  └─ Planner.plan_custom（自由任务）/ create_plan（预置场景）
       ├─ 模型按复杂度生成 DAG（1–5 节点）
       ├─ 复杂度判定 COMPLEXITY_CUES / _is_complex_task
       ├─ 复杂任务单节点 → _expand_complex_plan 补齐 analyze→build→test→review
       ├─ 平台核算任务 _is_platform_simple_task 强制单节点
       ├─ grounding 钩子写入平台独立核算用例（报名/会议室/AA）
       └─ DAG 完整性与环检测（不创建 Run）

POST /api/run
  └─ 创建 Run + 后台线程
       └─ Engine.run
            ├─ 持久化 ExecutionPlan（含 complexity 判定）
            ├─ Supervisor.ready_nodes
            ├─ ThreadPoolExecutor（同批最多 3 个节点）
            │    └─ Engine._run_node
            │         ├─ KnowledgeBase.search（BM25 经验）
            │         ├─ Scheduler.pick（四维评分 + 选择理由）
            │         ├─ 建立 Worker Session / 独立目录
            │         ├─ ContextAssembler.build（含上游交接产物）
            │         ├─ _demo_injection（仅演示首版注错，provenance=demo）
            │         ├─ LLM 或场景离线 produce（write_file / append_file…）
            │         ├─ ToolPolicy 授权与路径检查
            │         ├─ 写入 Worker 目录与最终 artifacts
            │         ├─ artifact.handoff（上游产物沿依赖边交接）
            │         ├─ Watchdog 截止时间检查
            │         ├─ Validator.validate（L1/L2/L3 + 平台独立核算 + 浏览器验收）
            │         └─ 失败：Self-Loop 归因 + Optimizer 决策 + Lesson + 携带证据重试
            └─ Run succeeded / failed

POST /api/runs/{id}/retry-plan   → 从未完成步骤携带证据续跑
POST /api/demo/selfheal          → 自愈演示（live；真实规划 + 核算 + 注错）
/api/agents CRUD + /api/agents/rank → Agent 定义配置与调度排序
```

## 软件交付 DAG（预置场景）

```text
                 ┌─→ 测试设计 ─┐
需求解析 ────────┤              ├─→ 编码实现 → 边界加固 → 交付评审
                 └─→ 风险审查 ─┘
```

## 自由任务 DAG（竞赛主证据，模型按复杂度生成）

```text
需求分析 ──analysis.md──→ 编码实现 ──index.html──→ 测试验证 ──test_report.md──→ 交付评审
 (分析)                    (编码)                  (测试)                     (评审)
```

实机 Run `20261116-112627-f43a61e1`：4 节点 4 角色，依赖边标注交接产物，编码/测试节点含自愈重试 ×1。复杂任务由模型规划，单节点时平台补齐此四角色链路；平台核算任务（报名/会议室/AA/CSV）强制单节点。

## 状态与证据

```text
Engine.emit
  └─ SQLite transaction
       ├─ traces（兼容展示）
       └─ events（游标协议）

Run Detail
  ├─ plan / nodes / steps
  ├─ worker_sessions
  ├─ verifications / feedback_cycles
  ├─ traces / events / lessons
  └─ final artifacts
```

trace 与 event 同时提交或同时回滚。事件使用全局递增 ID，客户端通过 `after` 游标读取新事件。

## 隔离范围

```text
Run A → Engine A → Scheduler A → data/runs/A/
Run B → Engine B → Scheduler B → data/runs/B/
```

Run 之间不共享临时调度统计。每次尝试的目录为：

```text
data/runs/{run_id}/workers/{node_id}/attempt-{n}/
```

最终可见产物位于：

```text
data/runs/{run_id}/artifacts/
```

## 来源标记

```text
deterministic → 程序、数据库、测试或健康检查证据
replay        → 场景离线产出
model         → 在线模型产出
mock          → Run 的离线模式标签
```

当前 L2/L3 均为本地确定性/启发式验证，不应描述成在线模型裁判。在此之上，**平台独立核算**（预期由确定性规则计算）与**真实浏览器验收**（页面行为断言）构成独立验证层，是“验证创新”的核心。

## 五大模块映射（赛题评分点）

```text
① Agent 定义与配置   router.py /api/agents CRUD + rank │ scheduler.py seed/rank/pick/report │ 监控台 Agent 配置页签
② 工作流编排         planner.py 复杂度规划 + DAG 校验 + grounding │ 工作台计划预览 │ 监控台分层 DAG
③ 任务调度与执行     scheduler.py 四维评分 │ engine.py Worker 会话/并行 │ policy.py / function_tools.py │ watchdog.py
④ 结果验证与监控     validator.py L1/L2/L3 + 平台核算 │ browser_check.py │ events.py │ 监控台证据/事件流
⑤ 反馈循环与优化     selfloop.py 归因 │ optimizer.py 决策 │ knowledge.py / context.py 经验复用 │ 工作台自愈叙事
```

证据：多 Agent Run `20261116-112627-f43a61e1`；Agent 配置 Run `20261116-113346-b183c6a6`；自愈 Run `20261116-113735-2c8e4efa`；盲测 `output/eval-blind-20261116-114104.md`（deepseek 5/5）。
